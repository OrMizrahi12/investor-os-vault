What goes to the cloud, and what stays here

Not running yet: it waits on the two steps below

One weekly check will run with your computer off. It reads only the copy on GitHub and opens no website. Everything that needs SEC, a price or your phone still needs this computer.

This does not move the system to the cloud. It adds one small job there. A task that reads filings would need your email, a wider network setting and a choice about Telegram, and those are yours to make.

Cloud run

The wall: .gitignore keeps everything in the "stays here" table out of every copy. The telegram file sits outside this folder, so it could not go anyway.

The way back: nothing comes back on its own, because this computer holds no GitHub key. You read the report on claude.ai or GitHub. To keep something, ask a session here to write it down.

What the weekly task does

Mondays at 09:00 UTC, on Opus 5.5, with no connectors. Prompt: Playbooks/Cloud weekly.md. It reports four lists, each line naming its file:

  1. Catalyst dates that passed with no Outcome written, and dates coming in 7 and 90 days.
  2. Reds and Oranges in the Journal with no Ruled: line.
  3. Decision checks and "Look again" dates that are due.
  4. What is still marked "For me".

It is not an alert and reads no news. A quiet report says nothing about any company. It recommends nothing, shows no price, and changes no rule. Rules/alerts.md did not change, and "nothing else sends an alert" still holds.

How you read the result

  1. On any device: open the task's page on claude.ai/code/routines, then History, then the run. The report is its last message. The Claude app's Code tab shows it too.
  2. On GitHub: the branch claude/cloud-weekly-<date> holds Research/<date> Cloud weekly.md.

What you do

An uploaded session was refused twice by the git proxy, on Nov. 4, 2026, your report. So the files reach GitHub through your browser, as one file, and a session started from the repository unpacks them. No token touches this computer.

  1. On the repository's GitHub page, choose uploading an existing file, add ~/investor-os-upload/investor-os.bundle, and commit it to main.
  2. In a separate terminal, not this session, type this line:
cd ~/investor-os && claude --cloud "This clone holds investor-os.bundle at its root. Run: git fetch ./investor-os.bundle main:refs/heads/vault-import, then git push --force origin vault-import:refs/heads/main. Change no file. Reply with the pushed commit's hash, or the error if it fails."

The force replaces your one upload commit, so only the vault's own history stays. The path was tested on this computer with a throwaway repository, not yet on GitHub. A newer copy later takes the same two steps, with a new bundle.
