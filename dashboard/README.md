# Dashboard

A local, read-only control board with five screens. Home answers "does anything need me today?" on one laptop screen. Company has one page for each note in `Companies/`, at `/company?company=GLW`. Ideas and alerts shows every company or lead at its stage, the rejection log, and every line the routines wrote, at `/ideas`. Portfolio and cash shows real first and paper under its label, with shares at the last saved close, at `/portfolio`. Journal reads the Journal and Lessons word for word, at `/journal`. The plan is `PLAN.md`.

**This is version 1 of the board, Nov. 4, 2026.** The number is in `VERSION`, and the browser tab shows it.

## Starting and stopping

| On | First, once | To start | To stop |
|---|---|---|---|
| **Linux** | Run `sh dashboard/launch/launch.sh desktop` | Double-click **Start board** on the desktop | Double-click **Stop board** |
| **Mac** | Double-click `dashboard/launch/Put on Desktop.command` | Double-click **Start board** on the desktop | Double-click **Stop board** |
| **Windows** | Double-click `dashboard\launch\Put on Desktop.bat` | Double-click **Start board** on the desktop | Double-click **Stop board** |

- **Start** starts the board, or reuses it if it is already running, and opens Home in the browser. A board on older code is restarted, because a running board keeps the code it first imported.
- **Stop** stops only the board that Start started. Nothing else on the computer is touched. A second click is harmless.
- **Anything else on port 8501 is left alone,** and the board takes the next free port, up to 8520. Start says so.
- **A first start on a new computer** needs Python 3.12 or newer, and the internet once. It makes `.venv` from `uv.lock`, through `uv` if it finds one and `pip` if not, and says so first. After that, starting uses no internet.
- **If the folder moves,** put the launchers on the desktop again, because they name its whole path. The Start and Stop files in `launch/` find their own folder, so on a Mac or Windows they also work from there.
- **A problem** keeps the window open with the words on it. The board's log and its record are in `.investor-os-board/` in your home folder, outside the vault.
- **A Mac** may refuse a file that came from the internet, the first time. Right-click it and choose Open. Its Terminal window stays open after the board has started, and it can be closed: the board keeps running.
- **Run by hand, for a look at its messages:** `dashboard/run.sh`. It stops with Ctrl+C, and Stop board cannot see it.

Keep it on this computer, because it holds Yahoo and Moody's data. New data shows on reload.

**Checked on Linux only (Xfce), Nov. 4, 2026,** by the launcher's own tests and a run through the system's launcher, including a first start with no `.venv` in a folder with a space in its name. **The Mac and Windows files have never run on a Mac or Windows.** Their branches are tested with the system calls stood in for, which shows what they would ask for and not that it works.

## Tests

    .venv/bin/python dashboard/test_dashboard.py
    .venv/bin/python dashboard/launch/test_board.py

The second one starts and stops the real board, with its record in a throwaway folder, so a board you have open is not touched.

## How it is built

It is read-only. No orders, no broker, and it sends nothing. Loading the page only reads files. For newer data, run a sensor by hand (see `sensors/README.md`), then reload.

- `.streamlit/config.toml` listens on this computer only, and turns off Streamlit's usage statistics and first-run email prompt. Those are Streamlit's defaults, so start it with `run.sh`, which reads this file. `app.py` shows no data if these settings are not active.
- `data.py` reads the files. It reuses the sensors' readers, so its numbers match `economy.html`. It does not import `edgar.py` or `watch.py`.
- `health.py` reads the "Financial health summary" in `Companies/Corning.md` and the tables behind its charts, then re-reads the saved filings and ties every number. Filing numbers come from the saved copies, never typed in. A number the latest 10-K does not report says so, and is tied to the filing it comes from. It does not read the note's status or thesis.
- `view.py` builds the tables and the chart. Text from notes is escaped, so a link or image inside a note cannot make the browser fetch anything.
- The catalyst panel reads only the newest file in `sensors/radar/runs/`. It never starts the radar and does not import it. A new run shows on reload, with no restart. A closer date or a larger rise looks the same as any other row, so no row is a level. The word tests leave out names and text the radar copied from notes and filings, such as "BEAD Buy America priority", but not the panel's own wording.
- What the radar hid is counted above the tables and listed in folded rows. A run saved before Nov. 3, 2026's ignore rules has none of these rows, and still reads.
- A company on the watchlist with no saved price shows "Unknown". The page does not fetch one.
- Portfolio and cash reads the notes in `Portfolio/` and the saved closes. Stocks count at the last saved close, as `Rules/cash.md` says. A position with no saved close is Unknown, and so are the total, every share and the cash level, with no fallback to cost. It says what would fill each gap. A note marked neither real nor paper is a problem, and none of it shows. It gives no recommendation. Room under the limit and names against bets stay "Not on file" until a saved `pm.py` run exists.
- The price against value panel reads only that company's newest file in `sensors/valuation/runs/`. It never starts `sensors/valuation/save.py`, does not import it or `value.py`, and reads no price file or note. A new run shows on reload, with no restart. It checks the file agrees with itself, and shows a problem instead of a figure if not. The band and lines are one date's values drawn flat, not past values. Its chart of what changes the figures is labeled as a what-if, not the method's answer.
- The panel shows the price, the two lines and what else the rules need. It names no zone for any close, my ruling of Nov. 4, 2026. It gives no recommendation and no status, thesis or holding. The Thesis status block above it is separate, under a fixed draft label that no argument turns off. Every zone looks the same: only the words differ, and tests check that.
- The Alerts panel, my request of Nov. 4, 2026, reads only `Journal/` and `.claude/guardrails/blocked.jsonl`. It shows what the routines wrote, by level, with each line's rule and source, when each routine last left a record, and what the guardrails stopped. It raises nothing of its own, judges nothing and sends nothing. Tests leave the panel's name and the lines it copies out of the word checks, and check its own words instead.
- Apart from those panels the page gives no buy or trim view, and it raises no alert on a price move or a source's age. Tests enforce both. On Nov. 3, 2026, with the method approved and the panel asked for, only the names "buy-below" and "trim-above" and one fixed sentence left the word check. Change those tests further only when the rules change: a change to my age limits or to the method.
- Each screen is a file in `screens/`, because Streamlit's test tool can only switch to a file-based page. A test covers every file there, so a new screen cannot escape the no-write and no-network checks.
- Home reads `Journal/`, the newest radar run, `Research/* kill criteria.md`, the notes in `Portfolio/`, each company's newest value run and the saved closes. It compares no close to a line. A `- Ruled:` line in the Journal closes one alert. A line it cannot match shows as a problem. Home and Portfolio and cash read the same book, so their shares agree.
- The Company page reads the note, `Research/`, `Catalysts/`, the Typed links tables, `Inbox/`, that company's value run, the saved close, `Journal/` and `Lessons/`. It says first what is missing and what would fill it. It sets no close against a line: the last close and the zones sit side by side, each with its date. Words copied from a file are marked `d-copied`, and a test checks they really are in the vault. A copied line with a figure and no dated source carries a visible tag, because the page cannot supply one.
- **The figure test** (`bare_figures`, `bare_labels`) reads what a reader sees, on all five screens and all 24 Company pages. A digit needs a dated source on its line, row, table caption or chart head. Fixed words may hold names and dates, and any other digit there needs a source. Headings and folded-section labels may hold no figure. Broken copies must fail. It checks that a dated source is there, not that the source says what the figure says. A copied line that a note leaves unsourced carries a visible tag that says what would fill it. Such lines cannot grow past the count the test holds, 31.
- **What is missing** (`missing_with_no_fill`): anything the page says it lacks must also say what would fill it, on the same line or row.
- **My age limits** are in `age_limits.toml`. Past one, the line says how old and what the limit is, as `This close is 9 days old, past my limit of 4 days.` Home has one line that names every such source, and the last column of "How old each source is" on Ideas and alerts has all of them. The words have no colour and no level, and a source's age alone stays no alert (`Rules/alerts.md`). A test holds the values, so a change needs my approval. If the file cannot be read, the words say Unknown, never within.
- **A failed sensor:** every screen shows what the Daily run's newest digest says about a failed sensor or a missing brief. That digest is written before the brief, so this still shows when a run dies. It is not on the waiting list, because only a routine's Journal line goes there.
- Ideas and alerts reads `Research/`, `Inbox/`, `Companies/`, `Journal/` and `Journal/decisions/`, the newest radar run, and the hunt's settings, for its watchlist. A company sits at one stage: its newest dated step, and on the same day the furthest. A row on the screen or a note on the map counts only when nothing else is on file. Every lead row says "A lead to read, never a pick". A coach file shows only my view and my decision. The look-again month is read from the words and sorts the log, and no row looks different for it. Waiting and Ruled come from the same reading as Home. The filters only choose what to show, and the line above the table names any Red or Orange they leave out.
- Journal reads `Journal/`, `Journal/decisions/` and `Lessons/`, and draws one part at a time, because the files are long. Its lines are word for word, each block or row carrying its file and day, and an entry is never rewritten, so a line with no source of its own carries no tag asking for one: the page says a figure there is what the file said on its date. Folds are plain markup, so opening one asks nothing of the server. The newest session comes first in a day, and the page says that "above" and "below" in a line mean the file's order. What we decided also counts the first entries' bold "We decided" line, written before the three headings existed. A lone "nothing" is counted and not listed. A "Correction to the session above" stays on By day and is no open item. Decisions shows my view and my words, with paper labelled, and data.decision_files never reads the system's view. Search is plain text and never reads a coach file. It shows the first 200 lines and counts the rest.
- `launch/` holds the launchers. `board.py` does the work, with the standard library alone, and the board never imports it.
- `tools/` holds checks by hand, and the board never imports it. `look_journal.py <folder>` drives every part of Journal in real Chrome. `broken_copy.py <new folder>` breaks the 8-K watcher on a labelled full copy, with the network dead and no token to find, runs the real collect and publish there, and saves what each screen says at each point. `look_broken.py <copy> <folder>` looks at that copy in real Chrome. `read_screens.py` saves a screen's words, and can move its own clock. `look_ideas.py <folder>` starts a fresh board and a labelled busy copy, and checks Ideas and alerts in real Chrome. `measure_home.py` measures Home in real Chrome, at `/`, since `/home` is not a page. `look_company.py <folder>` starts a fresh board and checks the Company page in real Chrome. `busy_copy.py <new folder>` makes a labelled copy of the vault with a busy made-up day, and refuses to write inside the vault. A `TEST_COPY.txt` in the copy puts a red banner on every screen. The app has no switch for made-up data: it reads the files next to it.
